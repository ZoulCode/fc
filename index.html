Lecture 1: مقدمة، أنواع الشبكات، Internet، Access Networks

لازم تكون عارف قبل ما تدخل ما في متطلبات. بس خلي في بالك: الدكتورة بتقيس على تعريفات دقيقة وجداول، فقراءة السلايدات قبل المحاضرة بتفرق كتير.
احفظ:
  • Computer network: نظام بيربط أجهزة مستقلة (بكيبل أو لاسلكي) عشان تتشارك المعلومات والموارد.
  • الأنواع الخمسة (من الأصغر للأكبر): PAN ← LAN ← CAN ← MAN ← WAN.

  • Internet = network of networks، وهو WAN، بيربط مليارات الأجهزة.
  • مكونات الإنترنت (6): Network edges (hosts/end systems) – Links & physical media – Network core (routers/switches) – Protocols – Applications – Hardware & Software.
  • Host / end system: أي جهاز فيه microprocessor ومتوصل بالشبكة (حتى الساعة والتلفزيون والعربية).
  • Packet: الـ end system بيقسّم الداتا لـ segments ويضيف header لكل واحد = packet. الـ receiver بيعيد تجميعها.
  • Switch vs Router: الـ switch بيحوّل الـ packets داخل نفس الشبكة، والـ router بين شبكات مختلفة. الاتنين اسمهم packet switches.
  • Route/path: سلسلة الـ links والـ switches اللي الـ packet بيعدّي عليها من المرسل للمستقبل.
  • ISP: بيوصّل الـ end systems بالإنترنت، وكل ISP نفسه شبكة، والـ ISPs لازم تكون متوصلة ببعض.
  • Protocol: بيحدد format و order الرسائل المتبادلة + الإجراءات اللي بتتعمل عند الإرسال/الاستقبال. أهم اتنين: TCP و IP.
  • التاريخ: 1961 Kleinrock (queueing theory يثبت فعالية packet switching) – 1964 Baran (packet switching في الشبكات العسكرية) – 1982 SMTP – 1983 DNS – 1983 نشر TCP/IP.
  • Access networks (3 أنواع): DSL – Enterprise Ethernet – Mobile.
    • DSL: نفس خط التلفون بيشيل صوت وداتا. الداتا (digital) بتروح للإنترنت عن طريق DSLAM في الـ central office، والصوت (analog) بيروح لشبكة التلفون. بيستخدم FDM (قنوات في ترددات مختلفة).
    • Ethernet: المستخدم عادة 100 Mbps أو 1 Gbps للـ switch. الـ switches ممكن تشيل firewall و proxy.
    • Mobile: الأجهزة بتتوصل لاسلكياً بـ base station.
أسئلة متوقعة
قارن بين LAN و MAN و WAN من ناحية المدى والتكلفة والصيانة.استخدم الجدول فوق: LAN حتى 2km، تكلفة قليلة وصيانة سهلة. MAN من 5 إلى 50km، تكلفة عالية وصيانة صعبة. WAN فوق 50km، تكلفة عالية جداً وصيانة صعبة جداً وسرعة قليلة.
ما الفرق بين الـ switch والـ router؟الـ switch بيحوّل الـ packets بين الأجهزة داخل نفس الشبكة، والـ router بيحوّلها بين شبكات مختلفة. (الاتنين packet switches).
كيف الـ DSL بينقل الصوت والداتا في نفس الخط؟بـ Frequency Division Multiplexing: كل نوع في band تردد مختلف. عند الـ DSLAM الداتا بتروح للإنترنت والصوت لشبكة التلفون.
عرّف الـ Protocol وأعطِ مثالين.Protocol يحدد format وترتيب الرسائل بين كيانين أو أكتر والإجراءات عند الإرسال والاستقبال. أمثلة: TCP, IP, HTTP, SMTP.
ليش الإنترنت اسمه "network of networks"؟ وهل هو WAN؟لأنه مجموعة شبكات (ISPs وشبكات مؤسسات ومنازل) متوصلة ببعض. وأيوه، السلايد بيصنّفه WAN.

Lecture 2: Wireless، Physical media، Circuit vs Packet switching

لازم تكون عارف قبل ما تدخل مفهوم الـ host والـ router والـ packet من Lecture 1. وتعرف إن الـ transmission rate بتتقاس بـ bits/second.
احفظ:
  • Wireless: WLAN (زي Wi-Fi، مدى قصير، بيت/مكتب) و WWAN (cellular 3G/4G/5G، مدى كبير، تقدمه شركات الاتصالات).
  • Physical media: Guided (الإشارة في وسط صلب: twisted pair, coaxial, fiber) و Unguided (radio waves).
    • Coaxial: موصّلين نحاس متحدين المركز، الداتا كهرباء.
    • Fiber: ألياف زجاج بتحمل نبضات ضوء (كل نبضة bit)، سرعة 10–100 Gbps، error rate قليل.
    • Twisted pair: سلكين نحاس معزولين. Cat 5 (100 Mbps – 1 Gbps) و Cat 6 (10 Gbps) حسب السلايد.
    • Radio: عيوبه: عوائق (obstruction) وتداخل (interference).
  • طريقتان لنقل الداتا في الـ core: Circuit switching و Packet switching.
Circuit switchingPacket switching

التلفون التقليدي، الصوتالإنترنت
  • FDM vs TDM: طريقتان لتقسيم الدائرة بين مستخدمين: FDM بالتردد، TDM بالزمن.
  • Transmission delay = L / R (L طول الـ packet بالـ bits، R معدل الـ link بالـ bps). تتحسب لكل hop. مثال السلايد: L=7.5 Mbit، R=1.5 Mbps → 5 ثواني للـ hop الواحد، وعلى hopين = 10 ثواني.
  • Store and forward: الـ router لازم يستلم الـ packet كامل قبل ما يبعته للـ link الجاية.
  • Queuing & loss: لو معدل الوصول أكبر من معدل الإرسال، الـ packets بتنتظر في queue، ولو الـ buffer امتلى الـ packets بتتفقد (dropped).
  • وظيفتا الـ core: Routing (تحديد المسار من المصدر للوجهة بخوارزميات routing) و Forwarding (نقل الـ packet من input الـ router لـ output المناسب باستخدام forwarding table بناءً على الـ header).
  • Internet structure: ربط ملايين الـ access ISPs ببعض مباشرة (كل واحد بكل واحد) ما بيتوسع (doesn't scale)، فنحتاج global transit ISP في النص.
أسئلة متوقعة
قارن بين Circuit switching و Packet switching (5 نقاط).استخدم الجدول فوق. أهم نقطة: Circuit بيحجز bandwidth ومخصص لكن فيه wastage. Packet بيتشارك ومن غير setup ومن غير wastage.
الفرق بين Routing و Forwarding؟Routing: تحديد المسار الكامل (network-wide) بخوارزميات. Forwarding: قرار محلي في الـ router، بينقل الـ packet من input لـ output حسب الـ forwarding table.
مسألة: packet حجمه 10 Mbit، الـ link 2 Mbps، والمسار فيه 3 hops (store-and-forward). كم الـ transmission time الكلي؟L/R = 10/2 = 5 ثواني للـ hop. على 3 hops = 15 ثانية (بإهمال الـ propagation والـ queuing). إضافة مني المسألة بنفس منطق مثال السلايد.
ما عيوب الـ radio waves كـ medium؟العوائق (obstruction by objects) والتداخل (interference).

Lecture 3: Performance، Security، Layers حسابات مؤكدة

لازم تكون عارف قبل ما تدخل معنى packet و link و router و L/R من Lecture 2. وحدات: 1 kbps = 10³ bps، 1 Mbps = 10⁶، 1 Gbps = 10⁹. و1 byte = 8 bits (مهم جداً في المسائل).
احفظ:
  • Performance parameters: Loss, Delay, Throughput.
  • Congestion بيسبب delay (الـ queue كبيرة) و loss (الـ queue وصلت أقصى سعة). الـ packet المفقود ممكن يتعاد إرساله من الـ node السابقة أو من المصدر.
  • أنواع الـ delay الأربعة:
    النوعالتعريفالصيغة
    Processingالـ router يقرأ الـ header (source, destination, length) ويفحص الأخطاءقيمة صغيرة جداً
    Queuingالانتظار في الـ queueD_queue(N) = (N−1) × L/R
    Transmissionوقت دفع كل bits الـ packet على الـ linkd_trans = L / R
    Propagationوقت سفر bit واحد على طول السلكd_prop = d / s (s ≈ 3×10⁸ m/s)
    الأكبر تأثيراً: Queuing و Transmission. الـ Processing و Propagation صغار. Transmission تعتمد على L، وPropagation تعتمد على طول السلك (دي من أكتر نقاط الخلط).
  • Throughput: معدل نقل الـ bits بين المرسل والمستقبل. Instantaneous (لحظي) أو Average. الـ link ذو الـ rate الأقل هو الـ bottleneck: throughput = min(Rs, Rc).
  • Security:
    • Virus: بيحتاج تفاعل المستخدم + بيحتاج host program. Worm: ما بيحتاج تفاعل، stand-alone، أسرع وأعنف انتشاراً.
    • Spyware: بيسجل الـ keystrokes والمواقع ويرفعها.
    • DDoS: (1) اختيار السيرفر الهدف (2) اختراق أجهزة حول الشبكة (3) إرسال packets للهدف من الأجهزة المخترقة.
    • Packet sniffing: interface في وضع promiscuous بيقرأ كل الـ packets في broadcast media.

  • OSI (7 layers): يضيف طبقتين فوق Transport: Presentation (تفسير الداتا: encryption، compression) و Session (synchronization، checkpointing، recovery). الترتيب: Application, Presentation, Session, Transport, Network, Data link, Physical.

Transmission = L/R = (2000×8) / (2×10⁶) = 16000 / 2×10⁶ = 0.008 s.

اشرح هجوم DDoS في 3 خطوات.(1) اختيار سيرفر الهدف (2) اختراق أجهزة كتيرة حول الشبكة (3) أمر الأجهزة المخترقة بإرسال traffic وهمي للهدف لحد ما الموارد (السيرفر أو الـ bandwidth) تنهار وما تخدم المستخدمين الحقيقيين.

  • Socket: الباب اللي الـ process تبعت وتستقبل منه. معرّف الـ socket = IP address (32-bit) + port number. أمثلة: HTTP = 80، mail server (SMTP) = 25.

  • الاتنين ما بيشفّروا. الحل: SSL في الـ application layer: بيوفر TCP connection مشفر + data integrity + end-point authentication. الموقع اللي يستخدمه URL بتاعه HTTPS.

Lecture 5: HTTP، Connections، Cookies، Web Cache حسابات مؤكدة

لازم تكون عارف قبل ما تدخل الـ client-server، الـ socket والـ port، وإن TCP بيحتاج connection. وإن RTT = الوقت اللي packet صغير بياخده من الـ client للـ server ويرجع.
احفظ:
  • Web page = base HTML file + objects مرجعية (صور، audio...). كل object له URL: www.someschool.edu/someDept/pic.gif (host name + path name). الـ host name يتحول لـ IP بالـ DNS.
  • HTTP: application layer، port 80، بيستخدم TCP. Stateless: السيرفر ما بيحتفظ بمعلومات عن الطلبات السابقة.
  • TCP 3-way handshake (في سياق HTTP): الـ client يبدأ connection على port 80، السيرفر يقبل، ثم يتبادلوا HTTP messages.
  • RTT = 2 × propagation time. وقت الطلب الأول = 2 RTT (واحد للـ TCP connection وواحد للـ base HTML).
  • Non-persistent: connection جديد لكل object (2 RTT لكل object). مزاياه: ما يضيع موارد، وأأمن. عيبه: CPU overhead أعلى.

Lecture 7: Transport Layer، Mux/Demux، UDP، Checksum حسابات مؤكدة

لازم تكون عارف قبل ما تدخل الـ socket (IP+port)، الفرق بين TCP وUDP من L4، والجمع الثنائي (binary addition) مع carry.
احفظ:
  • Transport vs Network: الـ Network layer = اتصال منطقي بين hosts. الـ Transport layer = اتصال منطقي بين processes. تشبيه السلايد: البيوت = hosts، الأطفال = processes، الرسائل = app messages، Ann وBill = transport protocol، البريد = network layer.
  • الـ transport protocols بتشتغل في الـ end systems فقط. المرسل بيقسم الرسائل لـ segments، والمستقبل بيجمعها.
  • وظائف Transport: multiplexing/demultiplexing، reliable data transfer، flow control، congestion control.
  • Connection-oriented (TCP): بيعمل handshake، reliable، ترتيب محفوظ، وبيتأكد من وصول كل الـ packets بدون أخطاء. Connectionless (UDP): بدون connection، كل packet وحدة مستقلة.
  • TCP: reliable، in-order، congestion control، flow control، connection setup. UDP: unreliable، unordered. الاتنين ما بيضمنوا delay محدد ولا security.
  • Multiplexing (عند المرسل): تجميع الرسائل من sockets متعددة وإضافة transport header. Demultiplexing (عند المستقبل): تسليم الـ segment للـ socket الصحيح باستخدام الـ header.
  • كل segment فيه: source port, dest port (+ IP addresses من الـ network layer).
  • Connectionless demux (UDP): بيعتمد على destination port فقط. نفس الـ server socket يستقبل من عدة clients.
  • Connection-oriented demux (TCP): الـ socket يتحدد بـ 4-tuple: source IP، source port، dest IP، dest port. الـ web server يعمل socket منفصل لكل client.
  • UDP header (8 bytes): source port, dest port, length (header + data بالـ bytes), checksum.
  • Checksum: لاكتشاف الأخطاء (bits مقلوبة).
خطوات الـ Checksum (احفظها بالترتيب) عند المرسل: (1) قسّم الداتا لكلمات 16-bit. (2) اجمعها كلها. (3) أي carry خارج من أعلى bit يترجع يتجمع على الناتج (wrap-around). (4) اعمل 1's complement (اقلب كل bit). الناتج هو الـ checksum.
عند المستقبل: احسب الـ checksum للـ segment المستلم وقارنه بالمخزن. تطابق = ما في خطأ مكتشف. عدم تطابق = في خطأ.

مثال السلايد (كلمتين 16-bit):

  wrap carry:  1011 1011 1011 1100
  complement:  0100 0100 0100 0011   ← الـ checksum

Lecture 8: Reliable Data Transfer، Flow Control، Congestion Control

لازم تكون عارف قبل ما تدخل الـ checksum (L7)، وTCP vs UDP، وفكرة الـ finite state machine (state + event + action).
احفظ:
  • Reliability = لا فقد بيانات ولا أخطاء bits. نفترض دالة rdt، ونبنيها تدريجياً بـ FSM (event يسبب انتقال state + actions).
  • rdt1.0: channel موثوق تماماً (لا أخطاء ولا فقد). Sender: ينتظر rdt_send(data) ← make_pkt ← udt_send. Receiver: rdt_rcv ← extract ← deliver_data.
  • rdt2.0: channel ممكن يقلب bits. الإضافات: error detection (checksum) + feedback من المستقبل: ACK (استلمت سليم) و NAK (فيه أخطاء). المرسل يعيد الإرسال عند NAK.
  • الخلل القاتل في rdt2.0: ماذا لو الـ ACK/NAK نفسه تلف؟ المرسل ما يعرف ما حدث عند المستقبل، وإعادة الإرسال ممكن تنتج duplicate.
  • rdt2.1 (الحل): المرسل يضيف sequence number (0 أو 1) لكل packet، ويعيد إرسال الـ packet الحالي لو ACK/NAK تالف، والمستقبل يتجاهل (ما يسلّم لفوق) الـ duplicate. هذا هو stop-and-wait: المرسل يبعت packet واحد وينتظر الرد.
  • المحاضرة وقفت عند rdt2.1.
  • TCP flow control: المستقبل يتحكم بالمرسل عشان المرسل ما يطغى على الـ receive buffer. المستقبل يعلن المساحة الفاضية بقيمة rwnd في الـ TCP header. المرسل يحد الـ unacked ("in-flight") data بقيمة rwnd.
    طريقتان بسيطتان: Stop-and-Wait (ACK لكل frame) و Sliding Window (ACK بعد إرسال عدد معين حتى تمتلئ النافذة اللي حددها المستقبل).
  • Congestion: "مصادر كتير بتبعت داتا كتير وبسرعة أكبر مما الشبكة تتحمل". مظاهره: فقد packets (overflow في buffers الـ routers) وتأخير طويل (queueing). مختلف عن flow control.
  • TCP congestion control (3 مراحل): (1) Slow Start: تبدأ ببطء والزيادة أسية (exponential) لحد الـ threshold. (2) Congestion Avoidance: بعد الوصول للـ threshold. (3) Congestion Detection: المرسل يرجع لـ Slow Start.

Lecture 9: Network Layer، Router، IP Addressing حسابات مؤكدة

لازم تكون عارف قبل ما تدخل التحويل بين binary و decimal (128، 64، 32، 16، 8، 4، 2، 1)، والفرق بين routing و forwarding (L2)، ومعنى الـ datagram.
احفظ:
  • Network layer: يحمل الـ segment من المرسل للمستقبل. عند المرسل بيغلّفه في datagram، وعند المستقبل يسلمه للـ transport. موجود في كل host وrouter. الـ router يفحص header كل IP datagram يمر عليه.
  • وظيفتان: Forwarding (يستخدم data plane) و Routing (يستخدم control plane).
  • Data plane vs Control plane:

    وظيفة محلية في الـ routerمنطق على مستوى الشبكة كلها
    يحدد كيف الـ datagram الواصل على input port يتحول لـ output portيحدد المسار end-to-end من المصدر للوجهة

  • Input port: physical layer (bit-level reception) ← data link (Ethernet) ← lookup/forwarding بالـ forwarding table ← switch fabric. فيه input buffer لو الـ datagrams أسرع من الـ fabric. أسلوب الـ forwarding: destination-based (تقليدي، بالـ destination IP فقط) أو generalized.

  • Switching fabrics (3 أنواع): Memory (الجيل الأول، تحت تحكم CPU، السرعة محدودة بـ memory bandwidth)، Bus (bus مشترك، bus contention، محدود بـ bus bandwidth)، Crossbar/Interconnection network (يتخطى حد الـ bus). الأمثلة: Cisco 5600 (32 Gbps bus)، Cisco 12000 (60 Gbps crossbar).
  • Input port queuing: لو الـ fabric أبطأ من مجموع الـ inputs يحصل queueing. HOL blocking (Head-of-the-Line): الـ datagram في أول الـ queue يمنع اللي وراه من التحرك.
  • Output ports: لازم buffering لما الـ datagrams تصل أسرع من الإرسال، والـ packets ممكن تضيع. Scheduling: FIFO، Priority، Round Robin. Discard policy (لو الـ queue ممتلئ): tail drop (ارمِ الواصل)، priority، random.
  • IP datagram format (32 bits في الصف): version – header length – type of service – total length – 16-bit identifier – flags – fragment offset – time to live (أقصى hops، يتناقص عند كل router) – upper layer protocol – header checksum – 32-bit source IP – 32-bit dest IP – options – data.
  • IP address: معرّف 32-bit لـ interface (مش للجهاز). الـ router عنده interfaces كتير، والـ host عادة واحد أو اثنين. مثال: 223.1.1.1 = 11011111 00000001 00000001 00000001.
  • Subnet: الأجهزة اللي لها نفس الـ subnet part (high-order bits) وتقدر تتواصل بدون router. وصفة تحديد الـ subnets: افصل كل interface عن الـ host/router لتحصل على "جزر" شبكات معزولة، كل جزيرة subnet. (شبكة السلايد 223.1.x فيها 3 subnets: 223.1.1.0/24 و 223.1.2.0/24 و 223.1.3.0/24. شكل "how many?" التالي في Kurose فيه 6 subnets.)
  • CIDR: a.b.c.d/x حيث x = عدد bits الـ subnet portion. مثال: 200.23.16.0/23.

Lecture 10: Data Link Layer، Error Detection حسابات مؤكدة

لازم تكون عارف قبل ما تدخل الـ datagram (L9)، وXOR: 0⊕0=0، 1⊕1=0، 0⊕1=1، 1⊕0=1. وإن الـ checksum بيعتمد على الجمع (L7).
احفظ:
  • مصطلحات: nodes = hosts + routers. links = قنوات الاتصال بين العقد المتجاورة (سلكية أو لاسلكية). الـ data link layer مسؤول عن نقل الـ datagram بين node وأقرب node متجاور عبر link.
  • بيحول stream الداتا لإشارات bit-by-bit ويرسلها. عند المستقبل يستلم الإشارات ويجمعها في frames ويسلمها لفوق.
  • موجودة في كل host، ومنفذة في الـ NIC / adapter أو chip (Ethernet card، 802.11 card). الـ datagram ممكن يعدي على بروتوكولات link مختلفة (Ethernet على link و802.11 على أخرى).
  • وظائف (4): Framing (تغليف packets الـ network في frames)، Addressing (hardware address، unique على الـ link)، Error control (detection: بسبب attenuation و noise. correction: المستقبل يصحح الـ bits بدون إعادة إرسال)، Flow control.
  • Protocols: Ethernet و PPP (سلكي)، 802.11 (لاسلكي).
  • Sublayers: LLC (multiplexing، تدفق الداتا، error messages، acknowledgments) و MAC (hardware addressing + التحكم في الوصول للـ physical media).
  • أنواع الأخطاء: Single-bit (bit واحد اتغير) و Burst (2 bits أو أكتر اتغيروا؛ مش لازم متتالية).
  • طرق الاكتشاف: Checksum – 1D parity – 2D parity – CRC.
  • 1D (simple) parity: بنضيف bit واحد (parity bit) لكل data unit بحيث عدد الـ 1s يصير even. عيوبه: يكتشف single-bit error فقط، ولو تغير bitين (مثلاً interchange) ما يكتشف.
  • 2D parity: نرتب الـ bits في جدول، نحسب parity لكل صف ولكل عمود، ونرسلهم مع الداتا. يكتشف ويصحح (single-bit error).
  • CRC: الأقوى وسهل التنفيذ. مبني على القسمة الثنائية (modulo-2) مش الجمع. نضيف R بتات للداتا D بحيث الناتج يقبل القسمة على الـ generator G. المستقبل يقسم على G: باقي صفر = سليم، وإلا يُرفض.
خطوات CRC (n = طول الداتا، k = طول G) 1) أضف (k−1) أصفار للداتا. 2) اعمل قسمة modulo-2 (XOR) على G. 3) الباقي = CRC (لازم k−1 بت). 4) Codeword = الداتا + CRC، طوله n+k−1.
مثال السلايد: D = 101110، G = 1001 (k=4):
1) 101110000   2) قسمة XOR   3) R = 011   4) Codeword = 101110011. 
101110000 / 1001  (modulo-2: لو أول bit = 1 اعمل XOR، لو 0 اكتفِ بالنزول)
1011 xor 1001 = 0010   -> نزّل bit  -> 0101 -> أول bit 0 -> شيله -> 101 + نزّل -> 1010
1010 xor 1001 = 0011   -> نزّل       -> 0110 -> شيله -> 110 + نزّل -> 1100
1100 xor 1001 = 0101   -> نزّل       -> 1010
1010 xor 1001 = 0011   -> R = 011

Lab 4: TCP/UDP + Telnet Quiz 2 يبدأ من هنا (Labs 4–7)

لازم تكون عارف قبل ما تدخل TCP vs UDP (L4، L7)، handshake (L5)، الـ ports، وأوامر interface و ip address (Lab 3).
احفظ:
  • TCP: connection يُنشأ قبل الإرسال. أشهر ports: FTP 20–21، HTTP 80، Telnet 23، SMTP 25. مثال: Client port 1027 ← Server port 80.
  • TCP header: 20 bytes. الحقول: Source Port، Destination Port، Sequence Number، Acknowledge Number، Header Length، Reserved، flags (URG, ACK, PSH, RST, SYN, FIN + NS, CWR, ECE)، Window، Checksum، Urgent Pointer، Options، Padding.
  • Three-way handshake: 
    1) Host A -> Server : SYN        (seq = a)
2) Server -> Host A : SYN, ACK   (seq = b, ack = a+1)
3) Host A -> Server : ACK        (seq = a+1, ack = b+1)
  • Transmission: الـ ACK يخبر المرسل بالـ sequence number المتوقع بعد ذلك (مثلاً إرسال 1,2,3 ثم ACK 4). لو ما وصل ACK، يعيد الإرسال.
  • Flow control (window): الـ ACK يحمل window (مثلاً ack 2049 window 2048) فالمرسل يحد الداتا حسب النافذة.
  • Termination (4 خطوات): FIN ← ACK ← FIN ← ACK، ثم الطرف اللي بدأ ينتظر TIME_WAIT = 2×MSL (MSL = 2 دقيقة حسب السلايد) ثم Closed.
  • UDP: بدون connection. header = 8 bytes (Source port, Dest port, Length, Checksum). لا ACKs فلا إعادة إرسال للـ packets المفقودة، وهذا مفيد للـ voice/video الحساس للتأخير. معرّض للـ duplication وعدم الترتيب.
  • Telnet: برنامج terminal emulation نصي ثنائي الاتجاه للإدارة عن بُعد (فروع بعيدة). بيستخدم TCP (port 23). الـ client يتصل بالـ server.
  • Authentication modes على VTY: None (بدون authentication)، AAA، Password (باسورد على الـ terminal interface).

Lab 5: ARP + Switching Quiz 2

لازم تكون عارف قبل ما تدخل MAC address و broadcast FF-FF-FF-FF-FF-FF (Lab 1)، الـ switch وcollision domains (Lab 3)، وإن Ethernet type لـ ARP = 0x0806.
احفظ:
  • ARP: يحول IP إلى MAC. الـ data link forwarding يحتاج MAC الوجهة. ARP يعمل داخل حدود الـ data link layer (ما في IP header؛ Type = 0x0806). الحقول: Hardware type/length، Protocol type/length، Operation code، Source/Destination hardware address، Source/Destination protocol address.
  • ARP cache: جدول مؤقت يعرض بـ arp -a (في الـ PC). الجهاز يفحص الـ cache أولاً قبل ما يرسل ARP request.
  • ARP Request: broadcast (Dest MAC = FF-FF-FF-FF-FF-FF في الـ frame، و 00-00-00-00-00-00 في حقل الـ destination hardware address داخل ARP)، Operation = Request. ARP Reply: unicast للمرسل، Operation = Reply. الـ receiver يتعلم MAC المرسل ويحطه في cache (Type = Dynamic).
  • Proxy ARP: الـ router/proxy يرد على ARP request بـ MAC الخاص بـ interface بتاعه بالنيابة عن الـ host في شبكة تانية (يتيح data link discovery بين الشبكات).
  • Gratuitous ARP: ARP request حيث Source IP = Destination IP (عنوان الجهاز نفسه). يُستخدم لـ اكتشاف تعارض الـ IP (IP conflict)، ويُرسل عند ضبط/تغيير الـ IP أو تشغيل الواجهة.
الـ Switch يعمل كده:
  1. البداية: الـ MAC table فاضية.
  2. Learning: يسجل الـ source MAC لأي frame داخل ومعه رقم الـ port.
  3. Flooding: لو الـ destination MAC غير معروف أو broadcast، يرسل الـ frame لكل الـ ports ما عدا الـ port الذي جاء منه.
  4. Forwarding: لو الـ destination موجود في الجدول، يرسله للـ port المحدد فقط (unicast).

Lab 7: OSPF اشرح بوضوح Quiz 2 ينتهي هنا

لازم تكون عارف قبل ما تدخل Lab 6 كامل (routing table، preference، static routes)، الـ multicast (L9، Lab 2)، وأمر network مع wildcard (عكس الـ mask: mask 255.255.255.0 ← wildcard 0.0.0.255).
احفظ:
  • OSPF: Interior Gateway Protocol (IGP) مبني على link-state. مزاياه: minimal routing traffic، rapid convergence، scalable، accurate metrics. بيشتغل حتى على MPLS.
  • OSPF Convergence: الراوترات تتبادل LSAs (LSA flooding) ← تبني LSDB ← تشغّل SPF algorithm ← تحصل على Shortest Path Tree ← تبني الـ IP routing table.
  • Router ID: 32 bit تعرّف كل راوتر (مثل 1.1.1.1). في اللاب نعيّنه يدوياً (عادة عنوان الـ loopback).
  • Network types: Broadcast (Ethernet — الافتراضي)، Point-to-Point (PPP و HDLC)، NBMA (ATM و Frame Relay — الافتراضي)، Point-to-Multipoint. تغيير النوع: ospf network-type p2p.
  • DR و BDR: في الـ broadcast networks لتقليل عدد الـ adjacencies. الـ BDR يتحول DR لو الـ DR فشل.
  • Neighbor vs Adjacent: حالتا علاقة. كل الراوترات في الـ segment جيران (neighbors) و 2-Way، لكن adjacent (Full) فقط مع DR و BDR.
  • الـ DR election: بناءً على Priority (الأعلى يفوز)، ولو تساوت فالأعلى Router ID. Priority = 0 ← لا يشارك في الانتخاب. Non-preemptive: لو جاء راوتر أعلى بعد الانتخاب ما ياخد مكان الـ DR.
  • Hello packets: لاكتشاف وصيانة الجيران. تحتوي: Router priority، DR، BDR، Hello interval، Router dead interval، Options، Neighbor.
  • الحالات (Link State Establishment): Down ← Init ← 2-Way ← ExStart ← Exchange ← Loading ← Full (+ Attempt في NBMA). Neighbor حتى 2-Way، Adjacent من ExStart لـ Full.
  • Database sync: يتفاوضون Master/Slave. DD (Database Description) تحمل LSA headers ← LSR (Link State Request) تطلب اللي ناقص ← LSU (Link State Update) تحمل الـ LSA كاملاً.
  • Cost (Metric): 10⁸ / bandwidth. تعدّل بـ ospf cost 20 (على interface) أو bandwidth-reference 10000 (تحت ospf) لتحسين الدقة مع الـ Gigabit.
  • Areas: Single area = LSDB واحدة (رقم أي area لكن area 0 هو الموصى به). Multi area = LSDBs منفصلة تقلل أثر التغييرات.
  • Authentication: simple password أو cryptographic (MD5).
  • Silent interface: يمنع الـ interface من تكوين neighbor relationships (لا يرسل hellos).
  • Timers الافتراضية: Hello = 10 ثواني، Dead = 40 ثانية (4×Hello)، Poll 120، Retransmit 5.
  • Multicast addresses: 224.0.0.5 = كل راوترات OSPF (AllSPFRouters)، 224.0.0.6 = الـ DR و BDR (AllDRouters).

DHCP — احفظ:
  • الغرض: توزيع IP وإعدادات الشبكة مركزياً بدل الضبط اليدوي (متعب وبه أخطاء).
  • 3 آليات للتوزيع: Dynamic (من pool مثلاً 192.168.1.10–252)، Automatic، Manual (عنوان محجوز لجهاز بعينه مثل 192.168.1.1).
  • الرسائل: DISCOVER (broadcast من الـ client لإيجاد servers)، OFFER (رد السيرفر بعرض)، REQUEST (الـ client يطلب العرض ويرفض العروض الباقية، أو يؤكد/يجدد)، ACK (تأكيد وتثبيت العنوان)، NAK (العنوان المطلوب ما ينفع)، RELEASE (الـ client يتخلى عن العنوان).
  • عملية الحصول (DORA): Discover (broadcast) ← Offer (unicast) ← Request (broadcast) ← ACK (unicast).
  • Lease renewal: عند بقاء 50% من مدة الـ lease: DHCP Request unicast للسيرفر ← ACK. لو ما نجح ← عند بقاء 12.5% (Rebinding): Request broadcast ← ACK/NAK. لو انتهت المدة بدون تجديد ← يتحرر العنوان (Release).
  • Address pools: Interface-based (dhcp select interface) أو Global (ip pool + dhcp select global).

الجزء الثالث: تمارين للتدريب (بحلول، حاول تحل قبل ما تفتح)

التمارين دي من عندي، بنفس نوع ومنطق مسائل السلايدات. الأرقام اتحسبت وتم التأكد منها.

أ) Delay و Throughput

1) packet حجمه 1500 bytes يُرسل على link سرعته 10 Mbps، طول الـ link 2000 km وسرعة الانتشار 2×10⁸ m/s. احسب d_trans و d_prop. L = 1500×8 = 12,000 bits. d_trans = 12,000 / 10⁷ = 0.0012 s = 1.2 ms.
d_prop = 2×10⁶ / 2×10⁸ = 0.01 s = 10 ms.
2) 10 packets وصلوا الـ queue في نفس اللحظة، كل واحد 4000 bits، والـ link 2 Mbps. كم queuing delay للـ packet رقم 6؟ (6−1) × (4000 / 2×10⁶) = 5 × 0.002 = 0.01 s = 10 ms.
3) مصدر Rs = 5 Mbps، link وسيط R1 = 2 Mbps، وlink للمستقبل Rc = 10 Mbps. كم الـ throughput؟min(5, 2, 10) = 2 Mbps (الـ bottleneck).
4) ملف 8 Mbit يُرسل على مسار فيه hopين (store-and-forward) كل link 4 Mbps. كم وقت الإرسال (إهمال الـ propagation)؟ L/R = 8/4 = 2 s لكل hop ← 4 s على hopين.

ب) HTTP و RTT

5) صفحة فيها base file و 20 صورة. احسب RTT في الحالات الأربع (parallel = 5 connections). Non-persistent بدون parallel: 2 + 2×20 = 42.
Non-persistent مع 5 parallel: 2 + 2×(20/5) = 2 + 8 = 10.
Persistent بدون pipelining: 2 + 20 = 22.
Persistent مع pipelining: 2 + 1 = 3.

ج) Checksum

6) احسب 8-bit checksum للكلمتين: 10110011 و 01101110. 10110011 + 01101110 = 1 00100001 (فيه carry). نرجّع الـ carry: 00100001 + 1 = 00100010. نعمل complement: 11011101. المستقبل يجمع الكلمتين + الـ checksum: 00100010 + 11011101 = 11111111 ← كلها 1 = سليم.
7) احسب 16-bit checksum: 1110011001100110 و 1101010101010101 (مثال السلايد). المجموع بعد wrap = 1011101110111100، والـ checksum (complement) = 0100010001000011.

د) Parity و CRC

8) استخدم even parity: الداتا 1011001. ما الـ parity bit؟ وماذا لو وصلت 1011101 مع نفس الـ parity؟ عدد الـ 1s في 1011001 = 4 (زوجي) ← parity bit = 0. 1011101 فيها 5 واحدات + parity 0 = عدد فردي ← يُكتشف الخطأ (single-bit error).
9) 2D parity (even). الجدول 3 صفوف × 4 أعمدة داتا: 1011 / 0110 / 1100. احسب parity الصفوف والأعمدة. Row parity: 1011 ← 1 (ثلاث 1s) | 0110 ← 0 | 1100 ← 0.
Column parity: العمود 1: 1,0,1 ← 0 | العمود 2: 0,1,1 ← 0 | العمود 3: 1,1,0 ← 0 | العمود 4: 1,0,0 ← 1.
الركن (parity of parity): نحسب parity عمود الـ row-parities (1,0,0) فيعطي 1، وهو نفسه parity صف الـ column-parities (0,0,0,1) = 1 (متطابقان).
لو انقلب bit واحد: الصف والعمود المتقاطعان يعطيان parity خطأ ← تحدد مكانه وتصححه.
10) CRC: D = 1101011111، G = 10011. احسب R و الـ codeword. k = 5 ← نضيف 4 أصفار. القسمة modulo-2 تعطي R = 0010. الـ codeword = 11010111110010 (14 bit = n + k − 1 = 10 + 4).
11) في CRC، D = 101110، G = 1001: كم طول الـ codeword وطول R؟n = 6، k = 4 ← R = k−1 = 3 bits، والـ codeword = n + k − 1 = 9 bits.

هـ) IP و Subnetting و Longest Prefix

12) IP 192.168.10.77/26. حدد الـ network و broadcast وأول/آخر host وعدد الـ hosts. /26 ← n = 6 ← block size = 64. 77 يقع في الـ block 64–127. Network = 192.168.10.64، Broadcast = 192.168.10.127، أول host = .65، آخر host = .126، عدد الـ hosts = 2⁶−2 = 62.
13) نحتاج 5 subnets من 10.0.0.0/24. ما الـ mask وكم host في كل subnet؟ 2³ = 8 ≥ 5 ← نستلف 3 bits ← /27 (255.255.255.224) ← 30 host لكل subnet. Subnets: .0 و .32 و .64 و .96 و .128 و .160 و .192 و .224.
14) Forwarding table: 11001000 00010111 00010*** → 0، 11001000 00010111 00011000 → 1، 11001000 00010111 00011*** → 2، otherwise → 3. حدد الـ interface لـ DA = 11001000 00010111 00011100 00000001. يطابق الثالث (00011***) فقط، لأن الثاني يتطلب 00011000 والعنوان فيه 00011100. ← Interface 2.
15) أي class لكل من: 10.5.6.7، 130.1.1.1، 200.1.1.1، 230.1.1.1؟ وأيها private؟ 10.x ← A (private)، 130.x ← B (public)، 200.x ← C (public)، 230.x ← D (multicast). الـ private فقط 10.5.6.7 من القائمة.
